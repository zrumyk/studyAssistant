Контрольне завдання A03. Маршрутизація мережевих подій

Розробіть простий двокроковий класифікатор подій. Це локальна симуляція. Мережеві запити та зовнішні сервіси не потрібні.

1. Окремим кроком запису створіть routing-policy.json. Для категорії auth поріг severity дорівнює 4, для dns — 2. Для відомої категорії подія з severity не менше порога має маршрут alert, решта має маршрут archive. Для невідомої категорії маршрут review незалежно від severity. Структуру й назви полів JSON обирає крок запису. Запишіть у політику всі правила, потрібні споживачеві.
2. Наступний крок Python читає саме збережений routing-policy.json як незмінний вхід. Не переписує цей файл та не дублює його пороги як робочі константи. Використовує лише стандартну бібліотеку. Фіксовані події у порядку входу: (a,auth,3), (b,auth,4), (c,dns,2), (d,dns,1), (e,other,5), (f,other,0). Записує decisions.csv з колонками event_id,route в тому самому порядку. Незалежні assert перевіряють повний набір, рівність порогу, невідому категорію, порожній вхід і вплив зміни порога в окремій тестовій копії політики. Записати checks.json із фактичними перевірками.
3. Звіт пояснює правила, передачу політики й фактичні результати. Використовує routing-policy.json, decisions.csv і checks.json. Формати DOCX/PDF. Підготувати матеріал захисту з поясненням граничних випадків. Для титулу застосувати глобальні налаштування.

Зберігайте відмінність між очікуваннями перевірок і виміряними результатами. Ручних дій немає.
