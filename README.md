# Майстерня навчання

Локальний помічник для навчальних робіт: матеріали → план → погодження → виконання → результати → звіт. Готова LLM працює через Ollama. Навчання або донавчання LLM не потрібне.

## Швидкий запуск

1. Запустіть `start.cmd`. Інтерфейс відкриється на http://127.0.0.1:18573.
2. У **Налаштуваннях** перевірте Ollama, Docker і шляхи інструментів.
3. Якщо Ollama ще немає, запустіть PowerShell у цій папці: `powershell -ExecutionPolicy Bypass -File scripts/setup.ps1`. Потрібно не менше 10 ГБ вільного місця на C:. Скрипт не видаляє файлів.
4. Перед завантаженням образів у Docker Desktop виберіть **Settings → Resources → Advanced → Disk image location** на D:. Сервер Docker має працювати в режимі Linux containers / WSL2.
5. Завантажте `qwen3.5:4b` і `embeddinggemma` через Налаштування. Для вже встановленої Ollama задайте `OLLAMA_MODELS=D:\StudyAssistant\models` і перезапустіть її перед завантаженням моделей. Портативний запуск робить це сам.
6. Для експорту PDF встановіть LibreOffice; для сканів — Tesseract з мовами `ukr` і `eng`, для сторінок PDF — Poppler. Задайте шляхи до EXE у налаштуваннях.

Програму вже зібрано в цьому каталозі. Для повторного встановлення тільки залежностей програми: `scripts/setup.ps1 -AppOnly`.

Після звільнення місця повне налаштування з документними інструментами: `scripts/setup.ps1 -DocumentTools`. Скрипт використовує пакети winget для LibreOffice, Tesseract і Poppler та офіційні мовні моделі Tesseract. Встановлення системних компонентів може потребувати прав адміністратора. Якщо winget не підтримує обраний шлях або пакет недоступний, повідомлення й ручні шляхи залишаються в Налаштуваннях.

## Як виконувати роботу

1. Створіть роботу: назва, предмет, умова, варіант за наявності.
2. У Матеріалах додайте методичку як **Завдання**, лекції як **Теорія**, чужий звіт як **Зразок звіту**. Для спільної бібліотеки підключіть папку з підпапками предметів. Назви предметів у проєкті й бібліотеці повинні збігатися.
3. Натисніть **Проаналізувати**, уточніть відсутні дані. Суперечності між методичкою і зразком вирішує користувач. Зміни вносіть у редактор плану або в завдання з повторним аналізом.
4. Перевірте кроки й залежності, натисніть **Погодити план**, потім **Виконати / продовжити**.
5. Помічник виконує доступні кроки. Для ручної дії поверніть опис результату; файли додавайте як **Мій результат**. За потреби можна явно підтвердити результат самостійно — це окрема позначка, не автоматична перевірка.
6. Перегляньте файли, журнали та звіт. Успішний запуск коду не доводить правильність усієї роботи. Звіт створюється лише після завершення змістових кроків.

**Хмара:** ключ Gemini додається в Налаштуваннях, DeepSeek — у `.env`. У режимі разового дозволу натисніть **Залучити хмару**, перегляньте текст і оцінку та дозвольте конкретне звернення. У режимі погодженого бюджету програма сама залучає хмарну модель для ремонту плану й коду та перевірки змісту звіту в межах лімітів. Непідтверджені мережні запити не повторюються автоматично. Облік бюджету стосується тільки цієї програми.

## Підтримка

- Вхід: PDF, DOCX, PPTX, TXT/MD, CSV/XLSX, PNG/JPEG; DOC/PPT через LibreOffice.
- Автозапуск: Python, JS/TS, C/C++, Java, C#, R, SQLite SQL, Octave. Образи готуються за потреби.
- Автоматичні сторонні пакети: Python, npm, R. Інші залежності потребують ручного кроку.
- AutoCAD, MATLAB та інше спеціальне ПЗ: файли, команди та ручні кроки. Octave не вважається гарантованою заміною MATLAB.
- Блок-схема плану зберігається у SVG, Mermaid та DOT. Спеціальні графіки й діаграми створюються кодом.
- DOCX з нумерацією, кодом, таблицями та ілюстраціями; PDF через LibreOffice. Формули зі сканів і складне оформлення потребують перевірки. PDF-зразок не відтворюється піксель у піксель.

## Ресурси й обмеження

Підготовка до захисту: після завершення плану окреме завдання створює defense.md, DOCX і PDF із теорією, етапами, розбором фактичного коду, результатами, запитаннями та усним виступом. Для старої роботи використайте кнопку у вкладці «Файли». У налаштуваннях можна вимкнути автоматичну генерацію. Пояснення перевіряються окремо; це не гарантія правильності всього посібника.

Матеріали семестру: D:/StudyAssistant/materials/semester. Екран «Бібліотека» показує розподіл за предметом і призначенням до імпорту. Каталог дозволяє впорядкувати файли без зміни оригіналів; однакові копії в одному предметі та ролі пропускаються. Читання/OCR та індексація виконуються у фоні. Докладно: [підготовка до захисту й семестрова бібліотека](docs/DEFENSE_AND_SEMESTER.md).

Одна важка операція одночасно, контекст 4096 токенів, контейнер 4 ГБ / 4 CPU. До трьох спроб виправлення кроку, до 10 хвилин на команду за замовчуванням. Загального ліміту роботи немає. Перед обчисленнями LLM вивантажується. Тайм-аут до 2 годин можна задати в погодженому плані.

Контейнери не отримують домашні папки, API-ключі, Docker socket або мережу. Завантаження й установлення виконуються окремо. Доступ до застосунку тільки локальний. Локальна модель невеликого розміру може помилятися: її фактичну якість потрібно виміряти бенчмарком, а результати роботи перевіряти.

Дані зберігаються у `data/`. Експорт ZIP знаходиться в роботі, резервне копіювання — в Налаштуваннях. Ключ Gemini зберігається в Windows Credential Manager, DeepSeek — у локальному .env. Обидва ключі не входять до резервної копії. Для відновлення зупиніть програму, розпакуйте резервну копію в новий каталог, задайте `STUDY_DATA` і запустіть сервер та worker із цим шляхом. Збережені абсолютні шляхи документів потрібно зберегти або оновити при перенесенні на інший комп’ютер.

Для файлів через браузер діє ліміт 100 МБ. Великі ZIP/NPZ та інші двійкові дані до 3 ГБ додавайте за локальним шляхом із роллю **Вихідні дані** або **Мій результат**. Зміст архіву не розпаковується під час імпорту; він зберігається як дані для окремої перевірки. Контрольна сума обчислюється потоково.

У Налаштуваннях можна вибрати окрему локальну модель коду. На цьому ноутбуці для перевірки використовується `qwen2.5-coder:7b`; основна модель `qwen3.5:4b` лишається для чату й зображень. Це не гарантує правильності складного коду. Незакінчена генерація може тривати кілька хвилин. Після трьох невдалих спроб крок зупиняється; новий повтор запускається явно. Детальний стан приймання: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).

## Розробка та перевірки

```powershell
$env:PYTHONPATH = "$PWD/backend"
.venv/Scripts/python.exe -m pytest
.venv/Scripts/python.exe scripts/benchmark.py
cd frontend
npm ci
npm run build
```

Бенчмарк не надсилає нічого в хмару. Успішна відповідь моделі ще не означає проходження: оцініть `data/benchmarks/latest.json`. Ціль якості — 10 із 12 сценаріїв; перевірки доступу й погодження мають проходити всі.

Сервер: `python -m uvicorn study.api:app --host 127.0.0.1 --port 18573 --no-access-log`. Worker: `python -m study.worker`. API-документація: `/docs`, після відкриття основного застосунку. API використовує локальну сесію та `x-study-token` для змін.

Зупинка: `scripts/stop.ps1`. Він зупиняє лише Python-процеси цього застосунку. Ollama та Docker залишаються під контролем користувача.

## DeepSeek API і локальний .env

Провайдер **DeepSeek API**, модель **deepseek-flash**. У кореневому `D:\StudyAssistant\.env` заповніть `DEEPSEEK_API_KEY=ваш_ключ` і збережіть файл. Порожній шаблон є в `.env.example`. Справжній `.env` та його локальні варіанти виключені через `.gitignore`, пакування вихідного коду та резервне копіювання. API повертає тільки ознаку наявності ключа. Значення читається при зверненні до налаштувань/погодженого запиту, без експорту до змінних дочірніх процесів; перезапуск після зміни ключа не потрібний.

Додавання ключа не є дозволом на API-виклик. Потрібен разовий дозвіл через «Дозволити цей запит» або явно ввімкнений бюджетний режим. В обох режимах фіксуються провайдер, модель, мета, текст та оцінка. Запит у стані quoted не можна відправити; зміна налаштувань не змінює вже підготовлений запит. Повтор ідентичної незавершеної відповіді чи запиту з невідомим результатом не оплачується автоматично; виправлення іншого модуля або за новим повідомленням про помилку є окремим запитом з новою перевіркою бюджету. Gemini має окремий адаптер і ключ у Windows Credential Manager.

Для DeepSeek бюджет рахується консервативно за піковими тарифами без кеш-знижок: $0.30 / 1 млн вхідних і $1.20 / 1 млн вихідних токенів, включно з міркуванням; локальний спільний бюджет — $5/місяць. Це оцінка за використаними токенами, рахунок провайдера може бути нижчим. Тарифи перевірені 19.10.2026: https://api-docs.deepseek.com/quick_start/pricing/. Сумісність запитів: https://api-docs.deepseek.com/api/create-chat-completion/.

Ключ перевірений реальними викликами. За останнім дозволом користувача активовано бюджетний режим: до $0,03/запит і $5/місяць. У Налаштуваннях можна повернути підтвердження кожного запиту. Наявність ключа сама по собі не активує цей режим.

Для економії режим міркування DeepSeek тепер вимкнений типово; у Налаштуваннях його можна ввімкнути, враховуючи, що reasoning також витрачає ліміт вихідних токенів. У зупиненому кроці можна вибрати «Використати вже отриманий код із хмари»: тільки завершену JSON-відповідь поточного проєкту й поточної версії плану. Це не створює нового API-запиту; після перевірки коду натисніть «Виконати / продовжити» для запуску в Docker.
