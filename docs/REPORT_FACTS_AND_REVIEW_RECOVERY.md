# SA-113/114 — Report facts and structured-review recovery

Report evidence now reads bounded CSV/JSONL/JSON artifacts and records read coverage, byte count and SHA256 when fully read. CSV outcomes are counted across all read rows, with separate passed/failed/unknown; all_passed requires complete reading, nonempty outcomes and no failures/unknowns. Named outcomes and failure examples are bounded samples. JSONL records expose case arguments/exit codes/timeouts without assuming that a nonzero exit is an incorrect result. JSON failures beyond initial shape samples remain visible. Files over the read limit, malformed files and facts that cannot fit the report context are explicitly incomplete/omitted. A full-file read is not a claim that every detail is printed in the context.

Maximum read2MB, named CSV outcomes60, failed CSV examples8, JSON failure examples8, JSONL case examples24. Context budgets remain bounded. Summaries describe program-produced observations; they do not certify lab correctness or the completeness of the generated checker. Source artifacts are not modified.

Accepted sections retain their old checkpoint files. For the same approved plan, profile, model and original evidence fingerprint, the program can locate the legacy section, reuse its text and reassess it against the new evidence. A negative reassessment invokes the usual bounded text repair; a positive one writes a new checkpoint. Changed evidence/profile cannot blindly inherit acceptance. No developer rewrites the student report.

A report ContentReview with json_invalid can open one distinct fresh assessment only after its parent receipt is done and the matching completed cloud job proves complete=true with identical raw text. Syntax is never repaired locally. Missing fields/type errors, truncation, unknown billing and valid negative verdicts do not open this path. The child uses normal standing budget/cancellation gates. An intent event is stored before dispatch and its child receipt identity after dispatch; on restart the child is revalidated locally, without a new request. An interrupted intent with no receipt stays unknown. A failed/invalid child creates no grandchild. Parent receipt/reserves remain immutable. This is limited to report review, not a general retry policy for all tools.

Offline verification includes late/unknown outcomes, truncated/malformed files, JSONL nonzero exits, legacy section migration, valid negative reviews, repeated invalid child/restart, interrupted intent, unknown parent and cancellation. Actual G02 evidence now exposes35 CSV checks and19 runs; its5 accepted checkpoints were not changed during inspection. Real continuation and rendering results are recorded separately in the worklog/evidence.
