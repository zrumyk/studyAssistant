# Архітектура

Браузер React спілкується тільки з локальним FastAPI через REST та SSE. FastAPI записує довгі дії в SQLite. Один worker захоплює завдання транзакцією BEGIN IMMEDIATE, виконує його й фіксує результат. OllamaProvider залишається тільки локальним. Окремий BudgetedModel керує дозволеним хмарним підсиленням: після локальних помилок, для ремонту та критичного рецензування; режим per_request виключає автоматичне платне підсилення.

## Дані

- projects: умова, стан, ревізія та хеш погодженого плану.
- documents/chunks/chunks_fts: незмінні копії джерел, локатори, текст і embeddings float32. Попередні версії зберігаються; пошук виключає superseded.
- steps: специфікація, стан, кількість спроб і докази виконання.
- jobs/events/messages: тривала черга, журнал подій і обговорення.
- artifacts: незмінні файлові знімки з походженням і позначками створення/виконання/застарівання. Звіти мають окремі каталоги версій.
- cloud_requests: точний текст, знімок тарифів, одноразовий дозвіл, резерв і фактичні витрати. Ключів у БД немає.

## Потік виконання

Аналіз → Plan (Pydantic) → перевірка посилань → редагування → погодження хешу → черга → Action (Pydantic) → перевірка аргументів → інструмент → результати/журнали → Assessment → наступний крок.

При невідомих даних або конфліктах погодження заблоковане. RuntimeError середовища зберігає код і передає крок користувачу без витрачання трьох спроб виправлення. Повторні помилки виконання обмежуються трьома спробами. Після перезапуску running стає interrupted/paused; повторний запуск потребує дії користувача. Залишені контейнери саме цього сховища зупиняються за owner label.

## Розширення

ModelProvider задає generate/embed/unload. DocumentParser повертає сторінки, попередження й профіль. RuntimeAdapter ізолює підготовку та запуск, ReportRenderer формує документ. Нові інструменти додаються в schemas.Step, engine та worker; кожен інструмент отримує тільки потрібні дані, не довільний доступ до host shell.

## Межі довіри

Документи, результати коду й вебвміст — дані, а не авторизація. Права визначає програма, не текст відповіді LLM. У контейнера лише знімок поточної робочої папки, без мережі, секретів і Docker socket. Завантаження даних і build залежностей — окремі операції. HTTP broker відхиляє приватні адреси, перевіряє redirects і фіксує перевірену IP-адресу з перевіркою оригінального TLS hostname; корпоративний proxy не використовується.

Великі джерела з workspace/inputs монтуються окремо лише для читання; вони не копіюються до кожного запуску й не входять у ліміт створених результатів 300 МБ. Зміна inputs з контейнера блокується. Python-перевірки передаються явними шляхами, зокрема вкладеними; кожна повинна містити assert. Оцінювач отримує фактичний вміст невеликих CSV/JSON/TXT навіть якщо модель пропустила expected_files. Наявність assert сама по собі не доводить незалежність чи змістову правильність перевірки.

HTML завантажених джерел читається як статичний текст без виконання скриптів. PDF із текстом та великими зображеннями додатково проходять OCR; попередження доходять до контексту пошуку. DOCX підтримує редаговані формули OMML; складне розпізнавання формул і верстка потребують перегляду.

Інтерфейс використовує same-site cookie, токен змін, перевірку Origin/Host і CSP. API доступний на 127.0.0.1:18573. Worker тримає локальний lock-порт 18574. Ключ Gemini зберігається через keyring у Windows Credential Manager.

## Поточні практичні обмеження

Модель на 4B не гарантує правильність складних робіт; дані benchmark мають оцінюватися окремо. OCR формул не вважається достовірним без перевірки. Читання сканів потребує мовних пакетів Tesseract. Не всі обчислення мають незалежний математичний oracle: зберігаємо exit code, перевірки та оцінку моделі окремо. DOCX/PDF потребують візуального перегляду; експорт PDF потребує LibreOffice. GPU для програм лабораторних у першій реалізації не передається; якщо CPU недостатньо, потрібен ручний крок.

Ці межі показуються через стани й повідомлення, а не замінюються вигаданими результатами або прихованим зверненням до хмари.

## DeepSeek і погодження окремого виклику

DeepSeek викликається тільки через фіксований https://api.deepseek.com/chat/completions. Назва моделі, провайдер, тарифи, ліміт відповіді й текст фіксуються в оцінці. Зміна налаштувань не перенаправляє стару оцінку іншому провайдеру. Стани: quoted → approved (після явної дії надсилання) → sending → done/failed/uncertain. Погодження та постановка в чергу атомарні; quoted не є дозволом. При невизначеній мережевій помилці зберігається резерв, автоматичних повторів немає. Обрізана відповідь позначається неповною. Gemini зберігає окремий формат запиту й ключ у Credential Manager.

DEEPSEEK_API_KEY читається з кореневого .env при потребі, без load_dotenv та змін os.environ. API повертає тільки has_cloud_key. .env не входить у settings JSON, snapshot оцінки, резервну копію, source ZIP або контейнер. .env.example містить порожній шаблон.


## Контрольні точки та бюджетний дозвіл

Успішний Docker результат зберігається перед оцінкою LLM. assessment_pending блокує повтор команди після відновлення; помилка оцінки та негативна критика зберігають фактичні файли й переводять крок на перегляд. Лише реальні помилки runtime/assert запускають автоматичний ремонт. prepared.stage_reviewed — внутрішній інтерфейс підготовленого локально коду з автором і причиною перевірки; походження позначається developer_reviewed, а не cloud_generated. Незавершені хмарні відповіді не стають кодом виконання.

cloud_consent_mode=budgeted є явним загальним дозволом користувача в межах cloud_request_limit_usd і cloud_budget. /cloud/{id}/send-budgeted перевіряє режим і ліміт, а перед фактичною відправкою перевіряється, чи дозвіл не відкликано. Кожен запит має незмінний snapshot і запис approval_kind. Типовий режим для нових установлень — per_request.
